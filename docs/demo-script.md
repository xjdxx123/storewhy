# Demo 脚本与提交材料草稿

## 三分钟演示

1. **场景，二十秒**：运营人员看到渠道费用上升，但新用户收入没有同步增长。普通报表展示数值，StoreWhy 帮助提出和检查解释。声明这是 Procrastinate Pro+ 公开教学快照。
2. **真实 Why，约八十秒**：提问“为什么2019年7月比6月费用增加，获客后14天收入却没有同步增长？”展示当前 paid/cohort/14天条件、Zetaris 证据与调查进度。在 Reviewer 要求补查后，展开按渠道执行的新 SQL 与 queryId。
3. **追问，约四十秒**：“只看FaceBoom”，再“窗口改成7天”。展示条件更新、证据 ID 变化和重新计算。可将七天保存为会话默认，再开始新分析，说明临时渠道不会自动沿用。
4. **能力边界，二十秒**：“是不是素材疲劳导致CTR下降？”系统解释缺少点击/曝光/素材字段，不能编造结论。
5. **Sponsor 与价值，二十秒**：Zetaris 负责实际数据分析；Nightshift 路由 NVIDIA 模型；H-MEM 保留有来源的偏好、纠正与审计。强调输出包含已核查事实、有限解释和下一步。

录制前通过 `/integrations` 核对连接，预跑一次主问题并检查延迟。若供应商失联，只能展示明确标注的自制 fixture 回放，不能称为 Live Agent。UI 由队友负责，正式录屏和截图需在 UI 接入后完成。

## Slides 内容

- 问题：增长团队缺少从“发生了什么”走向“为什么”的可检查调查过程。
- 产品：在明确数据范围内自由提问，按证据补查，承接多轮追问。
- 架构：React → TS API → Investigator / Reviewer → Zetaris；Nightshift/NVIDIA 与 H-MEM。
- 验证：独立数值基准、真实 SQL、固定/改写问题、多轮条件与故障测试；展示最新 evidence/agent-evaluation.json 结果，不提前填写通过率。
- 边界与下一步：真实数据连接、多平台口径校准、授权与部署；当前没有证明广告因果或提供预算优化。
